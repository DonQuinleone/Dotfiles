# Writing

- Always write in British English.
- Do not use em-dashes in any writing. Use commas, colons,
  semicolons or parentheses instead.
- Spell "e-mail" with a hyphen, never "email" (except in code,
  commands, addresses and domain names, e.g. `git send-email`).
- Wrap everything at 72 columns: code, comments, prose and commit
  messages alike. The exceptions are an aligned data table, where
  the columns are the readability and wrapping would destroy it,
  and any other line where wrapping would cost more clarity than
  it buys.
- READMEs and user-facing docs are written to the standard of a
  well-run open-source project, not generic boilerplate: they
  reflect the actual project (real names, URLs, commands), never
  placeholder-generic text. The good-readme skill carries the
  structure.
